# 施工场地布置

目标是完成用户本轮要求的实际图纸。自主选择查询、计算和修改方式，根据反馈继续决策；这里没有项目答案，也不规定工具顺序、调用次数或唯一算法。

## 先形成当前图纸的工作依据

通用执行脚本已注入本轮 `cad_context` 字典，可直接读取 `cad_context["input_files"]` 等字段；它不是需要 `import` 的 Python 模块。

- `cad_spatial_facts` 是部分 A：从当前 DXF 提取场界、编号/名称/面积表证据和跨图层轮廓分类，返回本轮 `facts_id`。继续查询沿用该编号，按需分页获取轮廓与问题；改动其源文件后重新分析。`machine_supported` 是图纸证据相互支持，不是人工确认。遮罩覆盖或视觉空白不等于空地。
- `cad_spatial_constraints` 是部分 B：传同一 `facts_id` 获取局部米制框架、轴向和约束，或检查完整提案；它不会布置整场，也不会生成 DXF。几何检查始终覆盖全部独立占地，不受返回页大小限制。
- 有独立证据时，可自主采用单位、候选场界和轴向作为本轮工作假设，并简要记录依据、冲突及适用范围；不把采用说成人审确认。没有可靠依据则补查，而不套用图签比例、历史角度或任意最长边。全部保留面和主要待定面均应避让；待定面尚非已确认建筑，不得为放下设施而删除或缩小它。

## 明确设施需求与面积口径

用 `cad_site_rules(facts_id=本轮编号)` 读取当前通用比例及对应面积预算。比例是概念方案的工作估计，不是施工规范；用户明确尺寸优先。说明分母是采用场界面积、建筑占地还是总建筑面积，不能混用。必要调整通过 `overrides` 明示，不为凑结果暗改比例。

默认研究范围为钢筋加工及堆放、模板堆放、周转材料、砌块及装修材料、临建办公、设备区域六类设施及连接道路。砂石堆场、塔吊覆盖和施工提升设备暂不默认加入；用户另有要求时再评估。可按需求分区，但分区面积之和仍需满足该类目标；放不下就比较其他位置或形状，并报告容量冲突，不静默漏项或缩小。

## 提案、反馈与修正

矩形的 `position_m` 是局部米坐标下、旋转前的左下角，也是旋转锚点，**不是中心**；`angle_deg` 相对局部框架。完整不规则面用 `vertices_m`。直接使用工具回传的真实中心、角点、净距和方向，不口算替代。

一次 `proposals` 列表表示同时存在的设施，会检查彼此碰撞。同一设施的互斥备选位置应分别检查，不能误把备选之间交叠当成场地障碍。确定组合后，对当前完整设施集合一同检查；单独新增一项不会自动记住未提交的旧提案。按越界、碰撞及净距反馈调整位置或方向，再检查完整集合。涉及道路还需查看连接关系，不能把面积够用视为已连通。

## 写出、回读与交付

预检没有冲突不等于已生成文件。可使用 `cad_layout` 的通用 `rectangle`/`road` 构件（`position_m`、尺寸、`points_m` 等），或自主 Python/CAD API，在本轮工作副本中实施。不要旋转原底图；在局部框架设计后映回 WCS。

使用空间证据发布契约，无需伪造顶层句柄或 `confirmed`：

```json
{
  "schema": "spatial-evidence/1",
  "facts_id": "本轮cad_spatial_facts返回的编号",
  "adopted_by": "agent",
  "assumptions": ["本轮采用的尺度、场界与轴向依据及保留的不确定性"]
}
```

可另给 `clearance_m`，采用本轮明确的非负米制净距并说明来源。将以上对象作为 `facts`，并传实际完整的 `components`，不能将部分 A 的大 JSON 塞入此字段。

保存后用 `cad_review(profile="site_layout")` 检查实际 DXF，提供同一证据契约与构件，或复用 `cad_layout` 保存的约定；查看与最终文件哈希对应的预览。修正后再次复核。简洁标注构件名称或编号与图例，避免用大段说明淹没图面。最终交付实际文件及检查范围；只能声明满足已采用的几何工作条件，不宣称规范验收、全面识别或人工批准。仍未完成的需求要明确保留，不用报告文件冒充已生成的场布图。
