# 恢复弹窗、执行过程与方位核查 · 2026-09-28

## 本轮范围与结论

用户确认关闭 Document Recovery 后模型立即恢复工作。本轮处理恢复弹窗阻塞与执行过程展示；核查方位角，不修改实际工程图纸，不关闭场布模块，不修改 DeepSeek 连接配置。本轮未重新调用模型生成场布，不能据此宣称场布质量已经改善。

## 1. FreeCAD 恢复弹窗

原 `gui_dispatch.py` 遇到模态窗口就暂缓派发，状态仍可能显示 healthy，排队预算又跟随模型设置的 timeout，最新工程任务因此出现 120、300、900 秒的等待。

修改位置：

- `freecad/start_mcp.FCMacro`：在宏入口立即为项目专用配置设置 `Document/RecoveryEnabled=False`，早于延迟启动 RPC 的回调。仅跳过启动恢复提示；不删除恢复文件，不关闭 AutoSaver。
- `freecad/mcp/addon/FreeCADMCP/rpc_server/gui_dispatch.py` 与 `dispatch_health.py`：记录模态窗口标题、阻塞状态和时间。未开始的排队任务立即取消并报告 `GUI_MODAL_BLOCKED`，关闭窗口后可接受新请求。
- `scripts/dev.py`：启动就绪检查读取 GUI 派发状态，不能仅凭 RPC socket 或 ping 联通启动智能体。
- `agent/prompts/cad.txt`：遇窗口阻塞不延长 timeout 盲重试；区分未执行与已开始的操作，避免重复写入。

实际验证：使用临时 profile 与独立内部端口，复制原恢复缓存后启动真实 FreeCAD。确认启动恢复提示被禁用，恢复文件逐字节哈希未变；打开真实 Qt 模态窗口，timeout=900 的请求在 **0.106 秒**返回阻塞错误。关闭窗口后新请求成功，被取消的写文件请求未补执行。另测执行过程中弹出嵌套模态窗口，**0.214 秒**返回 `operation_started=true / cancelled=false`，明确原操作可能在窗口关闭后继续；窗口关闭后原操作完成，新请求正常。隔离实例已关闭，未操作用户正在运行的四个项目服务。代表性的派发并发与健康回归通过，未运行全量 MCP 测试。验证仅证明这些具体场景，不能等同于任意 FreeCAD 操作都能自动解除阻塞；未知窗口不会被程序自动点击。

实现依据：[FreeCAD 1.1.3 启动流程](https://github.com/FreeCAD/FreeCAD/blob/1.1.3/src/Gui/MainWindow.cpp#L1714-L1749)先执行命令行宏，再检查恢复设置；因此无需修改 FreeCAD 本体源码，也不依赖不存在的启动参数。

## 2. 前端执行过程

- `frontend/src/components/ExecutionTrace.tsx`：同一用户轮次的助手消息合并，执行时展开过程；结束后默认折叠，用户可重新展开，刷新后可恢复历史。
- `frontend/src/components/ChatPanel.tsx`：按用户轮次组织消息，不再为每个工具调用单独重复助手头像。
- `agent/progress.py` 与 `backend/app/api/chat.py`：历史和实时事件共用公开反馈投影。显示动作、单位待核实、实体统计、复核问题、未完成检查、文件指纹和耗时；不把 MCP completed 直接解释为操作成功。
- `agent/prompts/cad.txt`：主要阶段变化或关键失败时输出简短公开进度说明，不要求逐工具播报，不额外调用模型生成摘要。内部 reasoning、系统上下文及脚本全文不透传到前端。

验证使用真实任务 `7538566c97b24d4584937e1563b25a25` 的45次工具事件只读回放，包括18次异常/未知结果和27次返回。历史与实时投影一致；浏览器验证运行时展开、异常详情可见、手动折叠不被后续更新打断、完成后自动折叠、45次操作可回看、刷新后默认折叠。前端构建通过。回放使用原图预览和原始工具记录，没有伪造工程执行成功。

## 3. 方位角：已定位，保守处理

对本次输入及最终候选 DXF 做只读量测：

| 对象 | 原世界坐标中的方向 |
| --- | --- |
| 新增14个矩形设施 | 26.400038° / 116.400038° |
| 4栋主体厂房 INSERT `1204、11EE、127A、1253`，应用实例变换后的轮廓 | 44.266211° / 134.266211° |
| 红线 BAE9 的最小面积外接矩形 | 44.256053° / 134.256053° |

设施与厂房主轴相差 **17.866173°**。模型对红线17个顶点做等权 PCA，得到26.4°并写入 facts.frame；后续变换正确使用了这个错误参考方向。因此不是图纸太差，也不是缺少坐标旋转功能。即使改成等弧长1000点，PCA仍约27.977°，单改采样不能解决问题。

本轮只补充轴向证据的提示约束，不硬编码44.266°，不旋转原图或既有设施。后续可靠方案：从已确认的主体建筑、道路边线提取候选轴，返回句柄、角度、支持长度及一致性，再用红线外接矩形交叉核对；候选冲突时保持现状或让用户选择。沿确认的局部 frame 计算新增设施，映射回原世界坐标，原图无需来回旋转。`cad_domain/layout.py` 已有局部/世界坐标转换，缺少的是可信 frame 的来源。

独立未解决项：当前障碍物清单遗漏上述主体 INSERT，单位0.6米/单位也需重新核实；此前复核器不支持带宽建筑轮廓的问题仍在。因此摆正方向也不代表可以通过工程验收。

## 使用与交接

正在运行的旧 FreeCAD、业务后端和智能体需正常停止后重新 `bash scripts/dev.sh`，新启动宏、摘要接口及提示词才全部生效。旧会话的工具记录也可生成摘要；新的阶段文字说明需要新一轮任务才会产生。
