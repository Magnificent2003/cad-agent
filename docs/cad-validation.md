# CAD 核心验证记录

使用项目提供的本地图纸验证；原图内容未覆盖；后续已迁到 `samples/private/`，未向模型发送图纸。机器可读结果见 `cad-validation.json`，派生文件位于忽略版本控制的 `data/validation/`。

## 环境

- Python 3.12，ezdxf 1.4.4，ODA File Converter 27.1.0.0。
- ODA AppImage 解包到 `cad_converter/runtime/squashfs-root`，入口为 `cad_converter/run.sh`。
- 当前安装包只有 Qt xcb 插件，使用 WSLg 的 `DISPLAY=:0`。文件系统沙箱阻止访问显示套接字时转换无法启动；在正常主机进程中已验证成功。无桌面服务器需安装 Xvfb 并启用 `ODA_USE_XVFB`。
- 初次验收采用 `DroidSansFallbackFull.ttf`；后续已改用项目携带的 Noto 中文字体和字符覆盖检查，见 [字体修复记录](font-compatibility.md)。原 DXF 字体样式不被改写。

## 预览性能与边界

真实总平面图的精确填充线曾使 SVG 达到约 564 MB；当前轻量预览仅画填充边界，完整填充保留在 DXF。相同图纸的 SVG 约 22.8 MB，元数据和预览生成约 28 秒；入口标识约 0.93 MB、2 秒。初版采用大图优先 PNG；后续按用户要求统一默认 SVG，仍可手动切换 PNG 或按工程坐标请求局部视图。本节体积和耗时及 `cad-validation.json` 为初次验收记录，最新字体渲染数据见字体修复记录。

自动化验证检查了文件可读取、单位、实体计数、布局、原生几何及文字，已人工检查生成的总平面 PNG 包含主要轮廓。尚未与 AutoCAD 原始出图逐像素对照；代理对象、外部图片、字体以及遮罩显示需要专业用户复核，预览不能作为完整格式保真的证明。

DWG 导出验证重新导入转换结果，比较有序实体的类型、图层、布局、关键原生几何、文字、块属性和单位。为兼容 ODA 十进制浮点序列化，使用 `export_tolerance=1e-7` 原生坐标单位的数值容差；该值不用于工程约束和规范距离。验证不认证所有专有对象内部结构。

真实总图文字修改也已验证：仅 TEXT 句柄 `12E0` 改变，26,466 个非目标图形实体的规范化序列化指纹保持一致，新版本完整产物生成约 40 秒。ezdxf 重写时会为 5,484 个空 `SEQEND` 分隔标记重新分配句柄；这些非图形标记单独写入变化记录，带应用数据或扩展字典的标记仍参与严格保真检查。

## 自动化用例

`tests/test_cad.py` 的 17 项通过用例覆盖：导入与源文件不变、模型/纸空间、区域预览、块属性及来源句柄、TEXT/MTEXT 修改、移动、新增折线/矩形/文字、未知单位确认、单位不匹配、非有限数值和坐标运算溢出、锁定图层、块引用和属性同步移动、拒绝直接修改块内部对象、保留非目标实体、几何 pass/fail/unknown/not_applicable、ODA 缺失和超时，以及停止 worker 时回收转换器进程。

复现命令：

```bash
uv run pytest tests/test_cad.py -q
```
