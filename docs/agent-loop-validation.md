# 智能体执行循环排查与复测

日期：2026-09-23。修改前检查点为 `9b1b810`。使用同一份实际施工图、同一个问题“简单介绍一下这张施工图”进行复测；没有把这张图的项目名称、指标或标准答案写入提示词。

## 确认的问题

1. **内部摘要被显示成用户答复。** 前端的 `Objective / Blocked` 来自引擎的压缩摘要。原先消息过滤只看消息片段，没有排除 `summary=true`、压缩代理等内部消息。
2. **截断与空答复被当成完成。** 原故障最后一条 CAD 消息以 `finish=length` 结束，没有正文；8192 个输出 token 全部消耗在推理上。结束原因、内部整理和实际答复没有被正确区分，用户因此没有收到正式结果。
3. **当前任务上下文被旧历史覆盖。** 历史摘要保留了已解决的缺库结论和上一轮路径；压缩后的自动续跑又没有保留本轮 `user.system`。实际生成的文件写进了旧任务目录，当前任务无法收集。
4. **查询覆盖与任务范围失控。** 已安装解析库仍被重复探查或手工替代；部分查询只覆盖顶层文字或最常见图块，遗漏低频引用里的关键信息。概述任务被扩展为渲染、导入和反复检查；第三轮一次不必要的整图导入耗时 113.361 秒。只减少调用次数并不能保证结果正确。
5. **工具错误反馈不完整。** GUI Python 异常只回传类型和简短文字，丢失失败前的标准输出、stderr 与出错行。模型自行调用 `traceback.print_exc()` 时，stderr 仍未返回，造成空的“成功”结果和多次猜测修复。

## 已实施的通用修复

- 在消息展示和任务完成判断中区分内部消息、正常正文、截断及空答复；异常停止后在原任务内续跑，保留相同输入与输出目标。**普通工具循环没有固定次数上限；仅截断或没有正式答复后的自动恢复最多 2 次**，仍不成功则明确标记失败。
- 每次模型调用、压缩和 Python 执行都重新读取后端绑定的当前任务。工具自动获得 `cad_context`；明确出现的旧任务路径会被拒绝。该机制防止误用历史路径，不是任意 Python 的操作系统沙箱。
- 更新模型容量配置；提示词强调按缺失证据选择操作、合并相关小查询、检查属性与被引用块、复用成熟库，并在证据足够时完成任务。保留原有通用 FreeCAD MCP 能力，没有添加针对本题的固定业务流程。
- GUI 与异步 Python 共同保留限长 stdout、stderr 和 traceback，包含原脚本行号；异步 GUI 回调继承本任务的输出路由，失败不额外请求截图。headless 原有错误回传保持不变。
- 在任务输入中提供已有 PNG 总览，减少模型为了观察布局而重复导入或生成截图。第四轮同题复测获得正确正式答复，没有额外导图、生成文件或修改原图。

## 同会话后续文件任务

在第四轮通过的同一会话中，继续要求将模型空间实体类型和数量另存为 CSV。结果为 **12.549 秒、1 次工具调用**，正常结束并发布可下载文件。

独立验证通过：从业务下载接口取得 CSV，重新解析原始 DXF 后逐项对照，16 种实体计数一致、合计 14217；下载内容与已登记成果的 SHA-256 一致。前一轮的输出目录仍为空，新文件只属于新任务；三个最终测试任务的 CAD 和预览输入哈希均未变化，结束后活跃上下文绑定已清除。测试会话已标注“验证”，原用户会话保留。

## 尚未解决的范围

这轮修复针对智能体执行与反馈链路，不代表所有工程问题均能正确完成。FreeCAD 原生导入导出的单位、坐标、图块、文字、中文及专业对象保真问题仍未解决；不同图纸版本和输入版本之间的兼容性也不能由本次概述测试证明。已有预览不保证包含所有对象，精确数值和文件修改仍须检查原 CAD 数据及导出结果。

模型输出具有波动性。当前改动保留自主探索能力，但仍需使用不同工程任务、跨轮修改和复杂图纸持续验证；不得将本题完成或某次耗时下降解释为普遍准确率保证。

## 本机端口现象

本轮重启时另遇到端口暂时无法绑定：Linux 没有对应监听进程，但 Windows 存在相同本地端口的 TIME_WAIT 连接。该主机的 TCP 动态客户端端口范围为 1024–15000，包含项目所用端口；Windows 连接释放后，WSL 中恢复可绑定。此现象独立于模型循环，不能一概判断为旧服务未退出。本轮未改 Windows 网络配置、项目端口或停止其他软件。
