# 为什么当前助手不能按绿色图框另存

更新日期：2026-09-22。前半部分记录原网页流程的能力诊断；下一阶段按用户澄清后的目标，优先接入现成 FreeCAD MCP，让 AI 自主编程操作文件。安装与实验入口见 [freecad/README.md](../freecad/README.md)。

## 不是没有写权限，而是工具不完整

当前 `agent/config.json` 允许全部 `cad_*` 工具，`agent/prompts/cad.txt` 允许直接执行用户明确要求的普通修改。CAD MCP 已连接，真实模型通过工具改文字并产生 r0002 的链路也曾通过验收。

但 `cad_mcp/server.py` 的 `apply_operations` 及 `backend/app/cad/editor.py` 只支持改文字、平移、新增折线、矩形和文字，没有删除、裁剪或创建独立图纸的实现。后端会拒绝不支持的操作。仅开放这些已有工具的权限不会增加动作；接入带有通用 Python 执行能力的工具环境，则可以让模型自行组合 API 完成更多任务。

已有的“另存”相关能力是生成同一图纸的修订版本和下载完整 DXF/DWG；缺少的是创建新的 drawing_id、保留来源关系，并让后续对话切换到独立副本。

助手如实说明没有删除工具是正确的，但将识别图框的负担转给用户、要求提供实体句柄，说明工具设计和交互仍不够完整。这次问题暴露了首期小范围功能验证与实际工程任务之间的差距。

## 为什么它看到了绿色框，却定位不了

- 查询主要面向模型/布局的顶层实体，INSERT 的块内实体没有递归展开。
- 未统一计算 BYLAYER、BYBLOCK、真彩色等规则下的最终显示颜色；图层为绿色不等于其中每个实体都显示绿色。
- 图框可能是闭合多段线、四条直线，或位于旋转、缩放、嵌套的图块中；只查 LWPOLYLINE 会漏掉。
- 目前 bbox 是保守包围盒，用于查询和预览，不能直接当成精确裁剪几何。
- 前端把 SVG 作为图片展示，没有候选图框高亮、点选和把选择传回工具的功能。

应当由程序枚举并高亮候选框；只有存在多个无法区分的候选时，再请用户点选。不要把截图像素当作精确工程坐标。

## FreeCAD MCP 为什么没有在首期安装

[初始指南](../CAD-Agent_Phase1_Deployment_Guide.md) 第 16 行明确把 FreeCAD MCP 调整为可选扩展：二维图纸先采用自建 CAD MCP + ezdxf + ODA，避免额外的对象导入导出映射。指南列出的首期编辑范围也只有上述基础操作。因此首期接入的是范围较窄的自建 CAD MCP。FreeCAD 现在作为独立实验接入，尚未替代网页中的业务流程。

“FreeCAD MCP”不是一个唯一、统一的工具包。不同社区实现提供不同工具，例如 [neka-nat/freecad-mcp](https://github.com/neka-nat/freecad-mcp/blob/main/docs/tools.md) 提供文档/对象操作及 Python 执行；是否适合本项目，要固定具体实现和版本后验证。

FreeCAD 可以补充三维、参数化和一些几何能力，但不会自动解决绿色图框定位、业务另存、前端选择以及天正对象保真。二维实体先导入 FreeCAD 对象再导出，也需要核验信息是否改变。代理图形被炸开后可能丢失原专有语义，参见 [ezdxf 代理实体说明](https://ezdxf.readthedocs.io/en/stable/dxfentities/acad_proxy_entity.html)。

## 下一步先验证 AI 自主操作文件

先直接连接固定版本的现成 FreeCAD MCP，开放其 `execute_code`，由模型根据自然语言任务自行编写和修正 FreeCAD Python。先前提出的“优先为每种编辑补专用接口”不再是当前实施顺序。

1. 安装 FreeCAD、插件和原版 MCP，在独立智能体会话中验证工具调用。
2. 对简单图和真实施工图副本做无修改的导入导出，检查底层兼容性。
3. 让模型完成修改文字、移动、删除、另存；再测试绿色图框任务，重新打开输出文件验收。
4. 按实测结果区分文件兼容性、MCP 调用和模型推理问题，再决定适配或修改源码。

本轮原版插件与 MCP 工具代码保留上游实现。本项目新增的是安装、启动、实验会话和验收入口。FreeCAD 文件输出与网页版本发布是两个步骤；前者验证成功后再接后者。

## 后续产品接入需要处理的事项

验收任务：**用户指定绿色图框，系统生成保留图幅内容的新图，保留原图，并切换到副本继续分析。**

1. **定位与确认图框**：返回最终显示颜色、递归块路径及 WCS 坐标，识别矩形候选并高亮。普通唯一候选可直接使用；含糊时让用户点选。
2. **创建独立副本**：完整复制当前文档，记录来源图纸和版本，创建新图纸记录；编辑始终作用在副本上。
3. **先生成处理清单**：区分完全框内、完全框外、跨界和无法确定范围的对象，提供数量与预览。
4. **分层实现删除与裁剪**：先支持明确实体删除与完全框外对象删除；跨界线、曲线、填充、文字、块、代理对象分别设计规则。不能把“删除完全框外对象”宣称为“全部信息精确裁剪”。
5. **校验并发布**：调整现有校验以区分新增、修改、删除及附属实体，检查非目标内容、生成预览，再发布副本。前端切换到新 drawing_id，支持 DXF/DWG 导出和后续对话。

先用合成图覆盖颜色继承、嵌套块、旋转框、跨界对象和重复操作，再在这张真实施工图上本地验收。无法处理的对象明确列出，不能通过隐藏或移远来冒充删除。

以上是后续产品行为与验收要求，不代表必须先把每一项写成专用 MCP。模型可以通过通用执行环境组合操作；业务副本、版本发布和验证应在文件实验之后接入。
