## 实现安排

1. `cad_domain/`：少量共享 Python 模块，处理二维原生几何、事实来源与文件哈希、布局和交付检查；MCP 与后端使用同一实现。
2. 现有 MCP 增加 `cad_inspect` / `cad_layout` / `cad_review`。调用项目已有 Python 环境执行文件几何工作，无须新增服务或安装第二套几何依赖；FreeCAD GUI / 无界面通用执行继续使用。
3. 修改过的 DXF 在交付前声明检查范围。普通编辑按原实体保留／显式改动检查；场布还检查明确登记的边界、障碍物、设施和道路。未知或不支持不能记为通过。
4. 场布事实记录原输入哈希、单位与证据、边界及障碍物原生实体、局部坐标系。每次按当前文件重新建立设施占用，不复用失效的空地掩码；坐标变换只用于新增构件。
5. 最终图像从实际 DXF 渲染并反馈；文件变化后旧检查／预览失效。后端在发布前再核对。检查驱动的自动续跑有独立上限，普通工具迭代不设固定次数。

## 实现结果

- `cad_domain/geometry.py`：共享原生二维几何、带输入哈希的事实、实际 DXF 保留与几何检查。检查返回 `passed / failed / unknown`，提供实体 handle、位置、实际量测与要求；缺少场地事实仍能检查设施重叠及道路自身错误。
- `cad_domain/layout.py`：米制参数化矩形与等宽道路；只对新增构件使用局部坐标变换，回写原 WCS。每步重新建立当前占用；先检查完整批次，再原子写候选。移除／移动保存累计改动来源，短标签及图例与构件一起维护。
- `cad_domain/delivery.py` / `worker.py`：工具与后端共用检查实现；检查约定、实际 DXF 和预览按哈希对应。MCP 增加三个辅助工具，保留通用 Python 执行，没有增加端口或依赖安装步骤。
- 后端仅在正常答复、执行空闲、实际成果检查通过后发布修改过的 DXF；检查不通过时同一会话最多继续两次。超限不发布，取消时也不发布。原有异常答复续跑预算与之独立，普通工具循环不受固定次数限制。
- 大量实体／检查结果只给模型有限样本并标记截断，完整检查报告留在任务 scratch；不把失败记录写成成功能力。

## 过程中发现和修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| 道路重新读取被当作闭合面，连续操作失败 | 共享按实际宽度构造的道路占用；道路参与碰撞检查 |
| 高测量坐标下旋转矩形测量出现数值误差 | 仅量测时平移到局部原点并使用与坐标精度对应的容差；图纸坐标不变 |
| 预览元数据正确但 PNG 已损坏，仍能被误认作已有反馈 | 验证真实 PNG、内容哈希和附件上限；损坏缓存重绘；图纸／图片版本不一致不通过 |
| 图像在发给模型前就被记为已反馈 | MCP 确认图片字节后确认反馈；后端以实际发送的图片哈希确认。仅表示进入反馈通道，不证明模型视觉理解正确 |
| 预览目录可经符号链接写到任务外 | 统一检查派生 PNG、SVG、元数据路径 |
| 临时图未保留累计改动来源 | scratch 候选保存单独来源条目，继续绘图可继承；scratch 不因此成为交付成果 |
| 同版本只读复核清掉已发送的图片记录 | 相同 DXF 哈希保留图像反馈，文件变化则失效 |
| 删除最后一个设施后被当作未登记布局 | 区分明确空清单与未提供清单；仍有未登记设施时不能用空清单冒充完成 |
| 放弃失败图纸、只交付说明时，被未使用的坏约定阻断 | 无输出 DXF 时不进行 CAD 几何验收，原输入完整性仍照常核验 |
| 白色道路与白色标签重叠不可读 | 参数化道路改用灰色，实际预览已复查 |

## 验证结果

1. **代表性自动测试：140 项通过**，范围是本轮几何、布局、MCP、交付检查、任务文件、图片、续跑和运行配置；没有跑全量 FreeCAD MCP。另有任务绑定插件 **10 项 Node 测试通过**。修改文件 Ruff 与 `git diff --check` 通过。测试环境有一条已有 Starlette/AnyIO 弃用提示，不影响结果。
2. **历史真实失败文件只读回归通过**：`round1_validation.py` 检出 14 个设施中的 8 对面积重叠、道路 `C907` 零宽及自交。原生内容保留检查通过，原输入与输出哈希未变。单位／边界／障碍物仍未知；量测面积明确标作图纸单位平方，不编造米制工程结论。该脚本中的历史 handle 只用于回归样例，不是产品规则。
3. **真实 MCP 到 Python 工作进程测试通过**：临时独立图、两个设施、一条有宽度道路及已确认障碍物；真实 inspect → layout → review → PNG → 图片反馈确认，随后后端同一检查器再查通过。最终一次总耗时约 1.81 秒，PNG 为 864×576、7,880 字节；报告完整保存，原图哈希不变，无 stderr。不经过模型，不宣称为模型能力测试。
4. **真实模型场景通过**：通过与网页相同的上传／对话接口，新建明确标记的合成工程。模型自行测得主轴 31°，使用通用 Python 布置 6×4 m 办公室和 8×5 m 仓库，保留原坐标、单位、建筑和文字；独立量测要求为边界／建筑／设施间至少 1 m。共 6 次工具调用（1 次 inspect、4 次通用 Python、1 次 review），没有工具报错及检查续跑。实际 DXF 和同源预览均复核通过，成果发布成功。模型没有选择 `cad_layout`；它自由编写的成果仍接受统一检查，这条路径同样有效。
5. **检查失败驱动修正**目前由集成测试验证：实际不合格 DXF → 同一会话内部反馈 → 修正与重新检查 → 只发布一次。连续不合格即便写入假的 passed 字段也不能通过；检查或渲染期间取消不会继续／发布。本次真实模型一次通过，不能据此宣称真实模型失败修复率已有提高。
