# 场布能力接入规划（按用户纠正修订）· 2026-09-29

本版替代此前“注入7—11人工轮廓知识，再封装一键道路/设施布局”的方案。那种实验不能满足本项目的泛化目标，后续不得沿用。

## 输入与能力边界

- Agent 的项目输入只有当前原始图纸及正常任务目录；不注入人工核对记录、白桥句柄、固定主轴、既有道路路径或成功设施坐标。
- 部分 A 从当前 DXF 中寻找场界候选，跨图层解析闭合轮廓，以图内名称、编号、表格、几何和相互关系分类机器支持轮廓、保留候选、从属重复、待定与非建筑提示。机器支持不是人工确认。
- 部分 B 提供从当前证据计算参照轴、统一坐标与候选区域几何约束的能力。模型决定要检查或绘制哪些设施和道路；不接入此前一键规划整张场布的脚本。
- 全部可解析闭合轮廓参与识别，不等于每一个闭合线都被判为建筑。停车、图例和内部小框仍要区分；漏解析的曲线、专业对象和待定内容明确标记，不以未知推断空地。
- 旧人工核对图和一键布局只作为开发历史记录，不通过新MCP、Skill、任务上下文或测试答案送给模型。

## 分步实施与验收

### 第1步：通用A/B成为可调用MCP能力

新增 `cad_spatial_facts` 和 `cad_spatial_constraints`，复用现有FreeCAD MCP服务与任务绑定。A返回同图哈希绑定的事实编号和可分页查询的语义/几何结果；B接收事实编号及模型提出的局部坐标候选，返回方向、越界、完整包含/交叠、净距及待定区域反馈。没有人工review输入；没有旧布局器调用。

先用纯v0009的真实模型调用验证“工具能看见、能调用、反馈能被理解”。这一阶段暂不添加Skill，不将原型脚本的成功当作模型成功，也不要求一轮内画出完整场布。为避免GUI/发布机制混入识别能力实验，可用相同OpenCode发行版、相同DeepSeek配置和真实MCP的隔离实例；需明确该实例尚不验证网页成果发布。

阶段测试提示词可限定为只读分析，便于定位工具发现/参数/反馈问题。它不是后续完整任务的最终提示词，测试报告必须如实区分。

### 第2步：工具验证后，再加入简短中文Skill

确认真实模型能调用A/B后，技能仅介绍工具分工、如何使用事实编号、如何处理错误和何时保存后复核，不包含项目答案或一套固定的道路布局步骤。运行配置显式发现 `agent/skills`，仅开放该技能必要权限；仍不开放任意系统命令。模型需要的参数说明由中文Skill和工具返回提供。

### 第3步：完整场布与成果发布

新会话、纯原始v0009、唯一提示词“请你进行场地布置”。模型选择/生成候选，调用B约束、根据反馈修正，通过现有CAD操作能力写入实际DXF，再进行保存后复核。扩展成果检查约定以接收机器事实与嵌套实例；不得伪造人工confirmed或降级检查绕过问题。最终验证右侧工作台确有新版本、可打开和下载。

若第一轮无需修正便通过，只说明调用和交付成功；另一个有真实约束冲突的案例才用于验证自主修正。后台几何搜索次数不算模型循环次数；开发者途中修代码的那一轮不计为自主成功。对模型、权限、接口或泛化取舍分别记录，不把所有问题归结为提示词不足。

## 仍需正视的泛化边界

当前图内证据算法对有名称/编号和表格互证的对象更有把握。没有表格、没有清晰语义、多个冲突方向或多个场界时，需要保留候选和不确定性，后续可由模型主动查询其他证据；不能将本图答案写回程序作兜底。参数和判据必须是通用规则，不能以“在白桥看起来更像”为唯一理由调出一个通用阈值。

## 记录要求

各阶段保存源图哈希、代码版本、真实模型和MCP调用、反馈后的动作、失败/人工介入、时间以及实际成果。原始运行数据留现有运行目录，阶段性MD与必要图/代码保留在dev_log_0929。先验证第1步，再根据事实决定继续第2步或就性能/泛化权衡与用户讨论。


## 阶段一实测后的补充

真实调用与失败记录见[阶段一报告](空间能力MCP接入阶段一0929.md)。已暴露两类接口问题：全量诊断被OpenCode截断，导致关键观测不可见；只返回通过状态而省略位姿与实测量，导致模型把左下角当中心并自行估算净距。后续工具应提供足够精确且有长度边界的观测，不靠更长的提示词补救。

旧成果复核只支持confirmed和模型空间原生handle，与新机器证据/实例轮廓不兼容。完整布置前需扩展版本化成果契约，保持同源、回读和未知项处理；不将自动事实伪造成人工确认。

规则配置（各设施比例与可调整范围）属于通用业务输入，可以后续通过受控接口提供给模型；历史成功路网、人工确认轮廓及项目专属坐标则不提供。模型可以从当前图纸查证后形成工作假设，Skill不能把“不确定”一律变为反复要求用户决策。
