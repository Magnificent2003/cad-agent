# 部分 B 首轮实际布置 · 2026-09-29

本轮使用同一张真实 v0009，开发“规则配置 → 空间事实接入 → 正交路网与六类设施 → 保存后独立回读”的离线原型。目标是先核对几何执行能力，尚未接入网页 Agent 的自动调用，不把这次算法结果当成大模型能力提高的证明。

## 审查入口

- [最终布局 PDF](v0009_site_layout.pdf)：第一页空间核对图，后续页为实际交付文件的逐项检查。
- [可编辑 DXF](v0009_site_layout.dxf)、[PNG](v0009_site_layout.png)、[SVG](v0009_site_layout.svg)。
- [结构化量测报告](v0009_site_layout_report.json)：绑定实际输入/输出哈希、参数、决策、设施与道路句柄及检查结果。
- [规则配置](../cad_domain/site_layout_rules.yaml)：可以调整比例、明确面积、尺寸比例、分片、间距、道路宽度及搜索预算，不含本项目坐标。

## 本轮采用的决策

1. **自主采用尺度与作业场界**。依据厂房轮廓与面积表的一致性，采用1个原生坐标单位=1米；使用BAE9作为本轮研究作业场界，不称其为已核实的法定红线。原文件的INSUNITS=4与上述证据冲突，因此新文件声明改为6（米），实体坐标不缩放，原始文件不修改。
2. **面积按场地面积估算**。暂不推算总建筑面积。用户明确指定设施面积时优先采用明确值；缺失时按钢筋5%、模板3%、周转3%、砌块/装修2%、办公5%、设备2%计算。砂石堆场不再生成。
3. **建筑占地按实际量测**。17项确认/保留轮廓的场内并集为28,911.30㎡，不人为凑到40%—60%。11号轮廓部分位于候选场界外，保持原样；场外503.69㎡不计入场内预算。所有碰撞检查仍使用完整轮廓，不能因此裁掉建筑。
4. **待定不等于空地**。主要的未定轮廓暂作避让区，不改判为确认建筑，不要求逐一征询用户。明确道路侧石、停车、植物、表格和辅助层可依配置排除；小型背景对象不自动升级为建筑。临时避让并集与已确认/保留轮廓分开计量。
5. **正交轴仅用于施工布局计算**。44.2662115°/134.2662115°来自前一阶段事实，不写入通用算法。先在局部坐标里求解，再将新增实体映回原世界坐标；原图不旋转、不炸块。
6. **道路20%为软预算**。按连通和设施临路需求生成道路，不用无用道路凑满20%。预留按7.5%作软参考。6米路宽、1米研究净距、7米临路距离均为可改的本轮假设，未冒充规范阈值。外部出入口、车辆转弯与消防验收不在本轮通过范围内。
7. **允许完整面积分区**。同一设施可分成最多4个矩形，各分区面积合计必须达到原目标；不得通过偷偷缩小面积、删除一类设施或放宽避让来获得通过。找不到方案返回搜索失败，不声称几何无解。

## 实现位置与效果

| 文件 | 作用 |
| --- | --- |
| `cad_domain/site_layout_rules.yaml` | 保存可编辑规则及其研究假设来源 |
| `cad_domain/site_program.py` | 将用户明确参数与默认比例合并成面积任务书，检查预算与参数 |
| `cad_domain/site_plan.py` | 绑定同版空间事实，搜索正交设施，随设施布置延伸连通路网，保存原生DXF实体 |
| `cad_domain/site_plan_review.py` | 重新打开保存后的DXF，量测实际面积、全轮廓碰撞、方向、净距和路网连接，不直接采信规划器坐标 |
| `cad_domain/site_layout_report.py` | 重读同一个DXF，输出同源矢量PDF/SVG和PNG，单独显示未知保护区 |

生成器是可复用的几何候选工具，不是按v0009句柄或坐标硬编码方案。它也不是全局最优施工组织设计：本轮完成面积、轴向、避让和基本路网关系，未比较运输成本、工期、临建层数、材料吞吐或设备选型。后续由Agent选择/调整任务书及候选策略，再调用同一检查器；本轮尚未接入这一模型决策环节。

## 本轮失败与修正记录

1. **只用17个轮廓时，几何检查通过但语义范围不足**。首版六类设施完整，却侵入28个主要待定轮廓，其中包含JMD与疑似配电房。保留[首版图](v0009_site_layout_initial.png)作为失败对照，不称为可交付改进。随后增加主要未定轮廓临时避让，避免“未分类就是空地”。
2. **固定路网限制摆放**。加入临时保护后，三个顺序的有限搜索未能放全。原因之一是先画路，再强制所有设施贴近固定路网。改为放置设施时计算连通支路，路网与设施共同更新占地状态；面积和避让规则保持。
3. **端点距离估计过于乐观**。第二个完整方案独立回读发现equipment-1距实际道路面8.4302米，超过7米。规划器此前用“中心节点距离减半路宽”估算，忽略平端道路端部形状。现改为实际道路面的距离检查，拒绝该位置并继续分区搜索。没有放宽临路阈值。
4. 搜索开发中修复过一次变量重命名导致的NameError；该失败未产生有效交付，不影响原CAD或用户服务。

## 可重复运行

在仓库根目录执行：

```bash
.venv/bin/python -m cad_domain.site_plan \
  data/agent-tasks/786b4ced67ef4d1198bfe8bdf0359aee/input/drawing.dxf \
  --review dev_log_0929/v0009_outline_review.json \
  --output dev_log_0929 --prefix v0009_site_layout
```

可用`--rules 文件路径`替换规则，也可用`--overrides 参数.json`覆盖少量参数。示例：`{"facilities":{"office":{"area_m2":1800}}}`只覆盖办公面积。`planning.uncertain_keepouts="none"`可做对照，但会恢复未定建筑被占用的风险，应查看检查范围，不能只看passed。

本轮不启动FreeCAD、业务后端、模型服务或前端，不读写API配置，不改用户会话；保留现有其他开发改动。本案例已经用于开发调参，不能作为独立验证项目。
