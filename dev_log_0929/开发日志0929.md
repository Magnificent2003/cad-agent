## 一、方向判断：一个整体能力，分成两个部分

赞同把“建筑内外界定”和“沿参照边正确布置”作为下一阶段重点，但建议按共同的数据与反馈链组织，而不是分别增加两个孤立绘图功能。

整体能力暂称 **空间事实支撑的施工场布操作**，包含：

| 部分 | 要解决的问题 | 输入 | 输出 |
| --- | --- | --- | --- |
| A．图纸空间事实构建与核实 | 当前版本中，哪里是建筑、场界、既有设施和待确认区域？依据是什么？ | 实际 CAD、任务范围、项目阶段、已确认条件 | 可追溯的占用面、场界边段、候选方向、待确认项及空间核对图 |
| B．参照边约束布置与修正 | 对已确认事实，设施应沿哪条边、以什么方向放在哪里？修改后是否仍满足要求？ | A 的当前事实、设施尺寸、指定区域/参照边、退距等任务条件 | 可编辑候选 CAD、实际量测和冲突反馈，或缺少依据/搜索未成功的具体原因 |

两部分共用实际文件检查，**暂不需要另建“审查智能体”**。继续使用现有 Agent loop 和 MCP：模型选择查询、理解任务与比较候选，工具计算几何、执行修改和量测；反馈回到模型，决定补查、调整、澄清或结束。保留通用 Python 能力，不退回只允许固定动作的旧链路。

这里需要持续区分三件事：

- **几何存在**：原生 CAD 里确有某个闭合轮廓。
- **工程含义成立**：它代表本任务有效的某栋建筑/场界，而不是房间、图框、旧方案或未采用的定义。
- **对当前操作构成约束**：在当前阶段和任务规则下，这个区域是否禁止该类设施占用。

恢复了隐藏几何，不等于已确认其设计有效性；识别为拟建建筑，也不能直接替代施工阶段和设施用途判断。

### 2.2 对照现有实现：不是从零增加几何检查

| 环节 | 现有能力 | 下一步缺口 |
| --- | --- | --- |
| 建筑包含与相交 | `cad_domain/layout.py:_collision`、`geometry.py:check_dxf` 已使用 `covers` 和多边形交集面积；完全包含也会触发冲突 | 障碍物是否完整、语义是否正确、数值容差是否与单位一致 |
| 块实例变换 | `geometry.py` 已通过虚拟实体处理 INSERT 变换与嵌套，检查记录中可保留块路径 | 建筑轮廓解析要求过窄；复杂块中的多个闭合对象和辅助线缺少有依据的选择机制 |
| 带宽多段线 | 目前明确拒绝作为零宽占用面边界使用 | 需要区分显示表达、实际带宽区域和建筑边界语义，不能靠清零原图线宽解决 |
| 布置与旋转 | `layout.py` 已有局部/世界坐标转换、指定角度、有限网格搜索 | `frame` 没有可靠参照来源；缺“具体边段＋设施哪一条边＋退距”的约束和最终角差验证 |
| 占用更新 | 已登记设施在增删移时更新占用，逐个布置时也会加入 occupied | 通用脚本生成但未登记的构件、未确认主体建筑与跨版本变更可能不在状态中 |
| 文件审查 | 已保存后重读、核对源/输出哈希、绑定预览 | 检查对象和目标覆盖不足；同一文件哈希不代表检查完整 |

Astra 对 `overlaps()` 和完全包含的提醒在几何上正确，但**它不是当前代码已经证实的错误**。Shapely 的 `overlaps()` 不包含完全包含关系；现项目使用交集面积，下一步应核实被传入的对象是否正确、完整。[Shapely overlaps 文档](https://shapely.readthedocs.io/en/stable/reference/shapely.overlaps.html)

还有三个需要优先纳入改造的实现问题：

1. `_site(original, …)` 基于本轮原始输入解析场地；任一障碍物解析失败，当前会让全部场界/障碍相关检查跳过。错误没有指出具体失败实体，模型修改输出副本线宽也不能改变原始事实。应按对象返回成功/失败及影响范围，保留有效结果，同时明确未知部分阻止哪些结论，不能静默删掉失败对象。
2. 摆放阶段将道路之间的相交也当冲突，复核阶段却允许道路交会。两阶段应共享关系规则，而不只是共享多边形算法。
3. `coverage` 圆可以免于占地碰撞，但目前并没有因此获得塔吊覆盖达标检查。用户要求覆盖指定厂房时，必须列为独立目标；画出圆不等于达到覆盖要求。

## 三、部分 A：图纸空间事实构建与核实

### 3.1 从任务范围内的事实开始，不急于做全图通用识别

首轮限定为真实总平面图中的任务相关主体建筑、场界候选和已布置设施。将实体查询、块展开、编号/文字关联和局部视图结合起来，先产生候选，再核实角色。不能仅按图层名、闭合性、面积大小或可见性直接定类。

WIPEOUT 负责显示遮挡，不删除下方几何；核对图应另行突出原生几何并标注“预览中被遮挡”，保留原图不动。[ezdxf WIPEOUT 文档](https://ezdxf.readthedocs.io/en/stable/dxfentities/wipeout.html)

INSERT 可用虚拟实体在实际位置检查而无需破坏性炸开，但虚拟实体本身没有持久句柄，MINSERT 和 XCLIP 也需要单独处理。来源应记录为“源文件哈希＋INSERT 实例路径＋原块内实体标识＋累计变换”，不能把一个虚拟对象编号当成跨版本永久身份。未支持的裁切、变换或专业对象应报告限制。[ezdxf INSERT 文档](https://ezdxf.readthedocs.io/en/stable/blocks/insert.html)

### 3.2 最小空间事实记录

沿用现有事实与检查文件，先扩展必要字段，不新增数据库、独立服务或复杂场景图框架。

| 信息 | 最低要求 |
| --- | --- |
| 版本与范围 | 绑定实际源文件、当前工作文件哈希和适用任务区域；原始保真基线与当前占用状态分开 |
| 对象角色 | 建筑、场界、既有设施、道路、覆盖示意或待确认对象；记录设计/施工阶段是否已知 |
| 几何 | 世界坐标下的占用多边形；记录外环/孔洞依据、单位及必要的局部计算坐标系 |
| 来源 | 句柄、块实例路径、变换、编号/文字/量测证据和提取方法 |
| 核实状态 | 待核实、已核实、存在冲突、修改后待复核；不把模型写下 confirmed 当作核实完成 |
| 对当前任务的影响 | 是否禁止占用、是否要求避让、影响哪些布置/检查项，或还缺什么证据 |

带宽闭合线要按语义选择解释：若已确认是建筑轮廓的制图表达，可从其参考边界提取占用面并保留表达宽度；若代表实体带状区域，则需要实际包络。不能一律忽略宽度，也不能一律拒绝。多轮廓、庭院、房间与外墙应明确层级，不能自动取最大轮廓/凸包代替真实建筑。

单位是前置事实。不得用图签1:600直接推出0.6米/模型单位；要由实际标注、已知尺寸或面积及对象对应关系交叉核实。坐标偏移到局部原点计算可以改善大测量坐标下的数值稳定性，但保存时应映回原坐标，不改变图纸实际单位。

### 3.3 首个交付物：空间核对图

下一轮优先交付独立核对图和简短清单，至少显示：

- 场界候选及边段编号；尚未确认用途时明确标为候选，不能直接称为已确认用地红线。
- 主体建筑的占用面、编号和来源，包括本例7—10号厂房；被遮挡几何仍应可见。
- 当前新增/既有设施和待确认区域；未知区域不能默认计为空地。
- 与当前任务相关的未解析对象及缺口，便于判断哪里还不能做可行性结论。

只有范围覆盖得到核实后，才能把“场界减建筑”称为当前条件下的候选布置区域。它仍不等于已经满足交通、消防、吊运、地基等工程要求的可用区域。

## 四、部分 B：参照边约束布置与修正

### 4.1 明确“平行于谁”，方向与位置同时求解

不规则场地不存在统一适合所有设施的角度。应区分“沿某段场界布置”“与某栋主体建筑对齐”和“沿道路布置”，由任务意图与相关对象确定参照。

对已确认的直线场界，形成有来源的边段表：边段标识、端点、长度、方向、邻近区域及必要的共线合并依据。由端点计算 `atan2(dy, dx)`，同时明确需要平行的是设施长边还是指定边。方向比较按180°等价处理；正方形应另定参照边规则。曲线边界需明确局部切线/分段近似误差，首版不支持时直接说明。

**全场 PCA、最长边和最小外接矩形只提供候选，不直接决定布置角度。** 本例建筑轴44.27°与场界候选方向接近，是可核实的局部证据，不应硬编码进算法。

摆放时：

1. 模型选择有依据的参照对象、边段和区域；有冲突时补查或请求具体选择。
2. 工具按该方向生成设施的完整旋转多边形，在场界内侧的限定范围搜索位置。凹边界的有效内侧需结合完整场地几何判断，不能只按边的左右方向猜测。
3. 对每个候选同时检查场界包含、占用冲突、尺寸和已确认退距；不能先找位置，最后旋转了事。
4. 返回可行候选及必要量测；无候选时返回阻碍对象、搜索范围、分辨率和预算。有限搜索未找到位置，不等于数学上已证明全场无解。

首版采用现有有限搜索的扩展即可，不提前承诺全局优化，也不为得到结果自动缩小尺寸、减少必要设施或放宽退距。

### 4.2 约束必须按角色解释

对一般禁止相交的设施占用面 P、确认场地 S、当前禁占区域集合 O_t，至少核对：

- 完整范围在场地内，可用 `covers(S, P)` 表达；它允许边界接触，若任务禁止贴边，应另加退距要求。[Shapely covers 文档](https://shapely.readthedocs.io/en/stable/reference/shapely.covers.html)
- `Area(P ∩ O_t) ≤ ε_A`；新增设施也参与后续的占用关系检查。
- 设施尺寸、与所选参照边的角差、必要净距满足任务要求。

长度、面积与角度容差应分别声明，按已核实单位和文件精度设定；不能把一个容差混用于所有关系，或通过大幅容差掩盖越界。若场界判定引入容差，也需限制实际越界距离。

角色规则至少区分：塔吊覆盖范围与目标建筑可相交且需量测覆盖；基础、堆场等是否可占用某阶段建筑范围由明确规则决定；道路交会可允许，但道路穿越禁止占用区域需检查。首版不宣称完整道路可达性、转弯半径、吊运或施工规范验收已覆盖。

### 4.3 当前状态与最终成果共用事实，但不盲信自报结果

每次增删移后，从实际当前文件刷新相关占用状态；通用 Python 修改也应接入这一过程。基线建筑发生授权变更时，原事实及相关检查进入待复核，不能因源哈希仍一致就继续套用旧位置。

先采用正确的全量重读作为可靠基线。只有实测全量成本确实成为问题，再研究依赖关系与局部复核；不能用“故意不更新”的坏基线证明新方法有效。

最终检查仍读取保存后的 DXF，并把以下内容绑定到同一文件版本：目标构件完整性、实际尺寸、边界与障碍范围、方向偏差、允许修改的对象，以及用户明确要求的覆盖等目标。部分检查未知不能计为全部通过，模型自行扩大 allowed_changes 也不能代替用户授权。

建议后续区分“可查看的研究草稿”和“通过已声明几何检查的候选”。检查失败时保留图纸、实际预览与定位反馈，让用户看到模型能力边界；草稿可见不等于放宽通过条件，也不等于工程验收通过。

## 五、下一轮只按三个阶段推进

| 顺序 | 工作与交付物 | 通过条件 | 不通过时如何收敛 |
| --- | --- | --- | --- |
| 1．先核实空间 | 固定真实 v0009 和任务，生成空间核对图、对象来源清单、单位/边界/阶段待确认项；先用人工核对结果建立开发参考 | 7—10号及任务相关建筑没有因遮挡/块嵌套漏掉；轮廓可追溯；未知范围可见；真实输入版本一致 | 优先修复杂块/带宽轮廓适配及对象角色核实，暂不扩大布局算法 |
| 2．人工事实下验证布置 | 使用同一底图和人工确认事实，沿指定边段放置实际任务中的棚、堆场等，并连续新增/移动/删除；输出 CAD 与检查定位 | 实际文件尺寸、角差、场界和占用约束满足约定，原图保持；失败可解释；修改后状态正确 | 修摆放、关系规则或序列化，不归咎于模型读图 |
| 3．接入实际 Agent 比较 | 将同一能力接入现有 MCP 和自主循环，记录自动识别、参照选择、调用参数、输出及复核；按原工程任务运行 | 能区分自动识别损失与执行损失；实际工程结果改善，成本与未完成项透明 | 依据证据只修失败环节，保留失败图和记录，不用简单合成图代替结果 |

优先扩展现有 `cad_inspect / cad_layout / cad_review` 的事实、参照和反馈协议，不新增独立端口，也不预设需要重写 FreeCAD 或 MCP。MCP 继续承载观察、动作及反馈，不替模型做所有语义选择。

代表性验证覆盖五类情形即可，暂不全量测试 CAD 服务：

1. 实际白桥图中的 WIPEOUT＋主体 INSERT，验证不会将遮挡区域误当空地。
2. 在真实建筑内部放入较小设施，验证完整包含冲突确实被查出，而非只验证边线交叉。
3. 沿两段不同朝向场界布置，验证明确的参照边与旋转后完整范围，而非全场一个角度。
4. 连续新增、移动、删除并复核，验证占用释放/增加、方向与旧检查失效。
5. 尺寸/区域/退距受限而搜索未成功，验证不偷偷缩放、不少画对象、不虚报无解或成功。

每例保留真实输入、任务、关键事实、实际调用、输出 CAD、同源预览和检查报告。微型几何例子只能补充边界条件验证，不作为场布能力改善的主证据。

## 六、研究定位与最小预实验

### 6.1 候选研究问题

可以将研究问题表述为：**在二维 CAD 的空间语义不完整、局部显示受遮挡且编辑持续发生的情况下，如何让智能体获取可追溯的空间事实，并使参照选择、布局动作和成果检查持续对应当前工程状态？**

两个部分分别承担“事实是否可信、完整”和“动作是否受这些事实约束”。MCP 驱动的 CAD 闭环可以作为整体系统贡献，价值应通过真实 CAD 上的可重复操作、反馈修正与工程案例证明。单独使用 MCP、PCA、旋转矩阵或多边形交集，不足以据此宣称算法新颖。

值得验证的机制包括：依据当前决策缺口选择图纸查询；把参照对象与几何动作显式绑定；在连续修改中识别已失效事实，使其不能支持错误的完成判断。此处是研究候选，尚无本项目实验结果支持“显著提高”或“首创”。

### 6.2 先分离误差，再比较方法

首先做三段诊断：

- **人工确认事实 → 同一布置工具**：测工具和执行本身是否可靠。
- **自动提取事实 → 同一布置工具**：测空间识别带来的损失。
- **完整 Agent → 同一工具与检查器**：测任务理解、参照选择、调用和状态更新带来的额外损失。

人工确认事实是诊断参考，不作为自动系统已经具备的能力。随后用同一底模、图纸、任务条件、工具能力、检查器和预算，比较通用 Agent、固定前置核查、任务驱动取证三种策略。若需做模块开关消融，应明确测量的是工具能力增益还是决策策略增益，不能混在一起。

重点记录：

| 层面 | 指标与解释 |
| --- | --- |
| 空间事实 | 任务关键建筑漏检/误判、轮廓与人工参考的一致性、角色正确性及待确认范围；不能只报面重叠分数 |
| 布置结果 | 所有必要设施完成率、越界/建筑/设施冲突、参照方向误差、尺寸误差与非目标改动 |
| 闭环质量 | 错误完成声明、同类无效重试、修正后新增冲突、过期事实/报告被继续使用的次数 |
| 成本 | 总耗时及模型/工具/等待分项，工具次数、token、人工确认成本；模块前处理成本也计入 |

最终评价应独立读取交付文件并核对人工参考，不能直接抄生产检查器的 passed。构件未交付、主动停止、合理澄清与真正通过分开计数，不能靠拒绝生成取得虚假的高可靠性。

白桥已经参与开发，应继续作为开发案例。正式验证需要未参与调参的其他工程，按工程划分，不把同图不同裁切算成独立项目；先小规模配对重复测量，再依结果决定扩展规模。若固定核查已取得相同结果且更便宜，就收敛论文主线，不为模块名称预定结论。

与既有[论文研究计划](../manuscript/CAD_Paper_Outline_Research_Plan.md)保持一致：先把工程错误修好，再检验主动取证或状态一致性是否有独立收益；本轮不改论文创新点和结论。
