# 空间能力接入 Agent：阶段一 · 2026-09-29

## 本轮目标和结论口径

按用户纠正，当前输入只能是原始图纸；人工确认的7—11轮廓、此前成功道路网络、旧场布成果不能成为运行时知识。本轮先验证通用A/B的真实MCP调用与反馈使用，不以离线程序的成功替代DeepSeek成功，也不把只读实验说成网页完整场布交付。

本轮未加入Skill，未修改模型、API、生产提示词或前端。现有Agent系统提示仍沿用执行Python、读图与保存复核约定。工具描述新增中文能力说明。后续还要验证Skill触发和实际文件生成/交付。

## 实验设计

使用项目配置的 `deepseek-cad/deepseek-flash`、现有OpenCode发行版、真实stdio MCP和worker。每次建立新会话，只有原始DXF副本和正常任务上下文；不附历史聊天、人工审查JSON、旧成果或预览。模型自行决定工具调用，实验脚本不代调业务工具、不发送隐藏的业务流程提示。

本阶段不启动FreeCAD GUI、业务后端或网页，因此它验证模型—MCP链路，**不验证网页发布，也不评估GUI导入保真**。模型尝试GUI而失败应单独记为实验环境影响，不能算成空间算法失效。此隔离也不是OS级文件沙箱；通用Python执行能力的范围仍受现有提示约定约束。

### 实验1：未通过，主动中止

运行目录：`.runtime/spatial-stage1/20260929-202952-b5dbf427/`。

耗时96.767秒，中止前12次工具调用：A三次、B一次、GUI代码两次、RPC状态一次、无界面代码五次。已证明模型发现并调用新工具，但A/B返回重复的全量诊断与实例编号，单行JSON超过OpenCode的50KiB限制，被截断后关键观测不可见。模型转向重复脚本分析，无法据此判定新能力闭环通过。

### 实验2：只读分析完成，但存在额外调用和解释偏差

运行目录：`.runtime/spatial-stage1/20260929-203748-ea5ad79f/`。

提示词：

> 请识别当前图纸场界范围内的建筑、候选占地和待定区域，并给出施工布置的参照轴及避让约束。本轮只分析，不修改图纸。

90.848秒完成，12次工具调用：A一次、B两次（第二次分页取占地）、GUI代码两次、RPC一次、无界面代码六次。A/B完整结果均未截断。模型自行取得参照轴和避让约束，又用脚本查阅拆迁、名称和编号文字；所有调用由实际DeepSeek发出，期间未介入修代码或代它选择坐标。

源图与输入副本未改动，输出目录为空，符合只读任务。调用完成不能等同于答复全部正确，已发现需改进：

- 多次探测未启动的GUI，增加无效往返；后续Skill应说明按任务选择文件工具/GUI。
- 工具说“候选范围与面积表角色尚不能认定相同”，模型答复一度断言“不是同一范围”，随后又承认未核实，语气过强。
- 模型将诊断分组数说成实体数，如“6条含bulge闭合线”；实际是6组未解析边界诊断，组内可能多个实体。最终说明应引用对应计数口径。
- 几何保留候选不能表述成“非建筑”；参照轴也不能在结尾升格为“已确认”。

这轮的通过范围是工具可发现、可调用、观测能完整到达、可以完成只读分析。还没有验证实际布置后的自主修正、DXF交付或工程验收。

### 多设施反馈长度修复（工具协议检查，不是模型能力测试）

B完整计算后保存源图/事实/算法绑定报告，返回 `report_id`、全部提案状态与计数；明细按报告分页读取，默认反馈控制在38,000字节。50项提案的1,225组互查全部保留，摘要约26KB；代表检查中最大明细页37,758字节，没有为省文字而省掉碰撞计算。A也限制单次返回，完整几何仍在当前任务事实文件。

B不自动累计不同调用的提案。检查多个计划设施时须提交当前完整集合；读取report不添加设施。已保存到新CAD的对象应重新提取事实。这个边界避免模型将“单独检查新增设施”误当“已查设施间碰撞”。

### 实验3：观察到模型反馈修正，但最终坐标说明错误

运行目录：`.runtime/spatial-stage1/20260929-204906-2e21c890/`。

任务为[局部钢筋加工场地](空间约束真实调用任务.md)：原图、20×15米、自选厂房中心作为故意错误初始位置、根据碰撞反馈调整；没有预置建筑编号、坐标或成功位置。

114.634秒，6轮带工具的模型行动、7次工具调用（A一次、B四次、GUI代码两次）。发生了真实的“模型提案→工具冲突反馈→模型改位→再次检查”，不是开发者在后台代算并提交答案：

| 模型动作 | 实际工具反馈 |
| --- | --- |
| 自选8号厂房，初始20×15米全部放在该厂房内 | 相交300㎡，完全包含；另有待定轮廓交叠 |
| 提出三个替代位置 | A无已知冲突；B越界19.80㎡；C撞10号厂房95.13㎡且与待定轮廓交叠 |
| 选择A并微调，要求2米净距 | PF无已检测冲突，越界0，待定交叠0 |

**不能将这轮算作可靠交付。** 最终文字把 `position_m=(120,45.5)`（旋转前左下角/旋转锚点）称作中心；实际几何中心为 `(130,53)`。两次GUI换算都失败后，模型仍给出了错误的世界中心、四角和净距：实际中心为 `(40480334.58261,3144846.38084)`，实际场界最短距离8.52272米，不是答复中的约16米。该核对来自本轮已保存的PF检查报告，而非重新手工设计一个结果。

根因与处理：MCP参数描述只写“局部位置”，缺少锚点解释；默认摘要虽保留状态，却未返回实际中心、世界角点和实测净距，模型用自己的估算补全，产生错误。需要把参数锚点、实际计算坐标与必要量测一并反馈，减少二次换算歧义；仍须检验模型是否如实引用，不能以接口补充代替复测。本轮结束后再修改并创建全新会话，保留此次错误记录。

### 实验4：坐标反馈修复后的新会话复测

运行目录：`.runtime/spatial-stage1/20260929-205637-19ec1ee7/`。模型、纯原图及任务文本与实验3相同，没有载入上一轮的位置、报告或会话；本轮运行期间没有改代码或人工代选参数。

**65.345秒完成，6轮带工具的模型行动、9次工具调用：A三次、B五次、旧通用inspect一次。** 没有GUI调用，所有工具返回均未被截断。9次包括一次场界编号查询被拒后模型调整查询，不是9次全部成功。

实际轨迹：

| 阶段 | DeepSeek动作与工具观测 |
| --- | --- |
| 识别 | 自主调用A，得到当前图纸的建筑、候选与不确定信息；调用B取得参照轴与局部米制框架 |
| 初始错误点 | 自选8号厂房中心，正确换算左下角为(233.5580921,-27.4943945)，20×15米范围全部落入厂房，相交300㎡ |
| 再决策 | 查询占地、提出多处替代位置；反馈指出某方案与待定轮廓交叠90.94㎡，另一方案交叠28.58㎡；模型继续调整和比较 |
| 最终检查 | 单独复核选中的20×15米场地：左下角(500,-120)，中心(510,-112.5)，轴角偏差0°，越界0，保留/待定交叠0 |
| 结果引用 | 最终中文答复正确区分锚点/中心，引用实际中心WCS(40480722.22017159,3144993.1029287837)、场界距离24.96545米、最近保留轮廓距离22.33906米、最近待定轮廓距离29.27022米 |

源图和输入副本未变；本轮不生成CAD，输出目录为空。临时模型服务已退出，任务绑定清除。运行日志中的 `completed` 表示模型结束答复；本报告另外核对了具体调用参数、保存的几何检查和最终数值，才确认上述阶段结果。

这次**确实观察到由DeepSeek驱动的提案—反馈—改位—复核循环**，通过范围限于一个真实底图上的局部只读位置建议。它没有采用此前的道路或成功场布答案，实际最后位置也与实验3不同。没有Skill仍可发现工具，说明Skill的价值应是稳定使用和语义一致性，而不是预先断言模型完全不具备工具发现能力。

尚有两点明确记录：

- 模型将同一设施的互斥备选位置放在一个proposals列表中，工具按“同时存在”检测出两案互撞；模型把二者都排除，这会误减候选范围。最终单个位置已独立复核，不受该误排影响，但候选比选与同时布置需要后续Skill明确区分。本轮仅补清工具文字说明，没有再声称该使用习惯已经被模型复测修正。
- 模型曾用A的ids查询场界候选；旧适配只收建筑等分类ID，拒绝了合法场界编号。实验结束后修复为也可精确查询场界几何，保持分类计数不变；用同一真实源图复现该请求已通过。该小修正发生在实验结束后，最新源码哈希与实验4保存的哈希有此差异，未重复宣称又完成了一轮模型试验。

本次预算为几何约束观测，不含规范退距规则；模型最终查询的clearance_m=0，实测几何距离为正，不能据此声称已经采用了特定规范净距。施工阶段、法定边界、未解析对象等限制在最终答复中保留。中间部分进度消息用了英文，最终结果为中文；语言一致性也留待交互/Skill阶段改进。

## 后续实验与交付契约

实验3、4用同一纯图纸执行[局部钢筋加工场地任务](空间约束真实调用任务.md)，由模型自己识别并选择初始位置、读取冲突反馈、提出调整方案。它是故意包含错误初始位置的反馈实验，不是最终“请你进行场地布置”完整任务，也不以几何搜索循环代替模型重新决策。

新事实目前是机器证据/暂定占地，且有块内部的复合实例编号。旧 `cad_layout/cad_review` 接收的是 `confirmed` 和模型空间原生handle，不能直接把新结果改几个字段后塞入。Skill只能帮助模型使用工具，不能修复这个数据契约缺口；后续需要保留机器证据身份与源图哈希、支持实例轮廓的成果检查桥接，禁止伪造人审确认或改用general检查绕过。

完整场布仍按下一阶段使用唯一提示“请你进行场地布置”，新增中文Skill不应包含白桥编号、固定角度、道路路径或成功坐标。只有真实保存/回读/发布验证后，才将完整场布能力写入README。


## 下一阶段的具体入口

1. **中文Skill先帮助发现工具和解释反馈**：显式注册 `agent/skills` 路径，只开放对应原生skill权限；当前默认拒绝原生skill，单放一个文件不会生效。内容只讲A/B分工、候选/工作假设、位姿含义、完整候选集与错误反馈，不写项目答案，也不强制固定调用次数。先验证实际模型能加载Skill，不靠系统长提示替代加载证据。
2. **扩展成果检查的版本化空间事实契约**：旧接口的 `confirmed + 顶层handle` 无法表达块内实例、机器证据和保留候选。保留 `human_confirmed=false`，写明Agent采用依据、源图/算法绑定与未知项策略；绘制和保存后审查都从相同源实例解析几何。不能只放宽检查让结果通过。
3. **再做整场布实验**：全新会话、纯v0009、用户提示仅“请你进行场地布置”。由模型决定道路/设施候选并使用B反馈修改，保存DXF后回读实际文件与同源预览，经过后端独立检查，确认网页新版本与下载。期间改代码或开发者代选参数须重开实验并记录介入。

本轮结果只覆盖新增A/B在本工程上的工具调用；未证明独立工程泛化、规范合规、完整道路网络或自动交付。由于用户要求分步落实，这些后续步骤分别验收，不将阶段一包装为整项目完成。
